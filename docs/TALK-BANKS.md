# Talk banks reference

The offline world is generated and checked. Node and Worker asset readers, authenticated Talk routes, the Story panel, ambient chatter and packaging checks are integrated on the Phase 3 branch. Hosted, browser, provider and production acceptance remain separate gates.

## Bank format

`scripts/talk-factory/bank.ts` exports `parseTalkBankEvidence`, `validateTalkBank`, and `compileTalkBank`. A bank has seven topics: market, food, weather, work, city, festival, and directions. It accepts 60 to 150 unique English lines, with at most 140 characters per line and 32,000 bytes per bank.

The accepted voices are `plain`, `pidgin`, `formal`, and `jokey`. The accepted bank languages are `en` and `pcm`. The compiler validates source IDs, phrasebook references, topic coverage, uniqueness, text filters, and size before it returns a bank.

Phrasebook entries are human-sourced records with a citation and contributor field. The three current entries are beta candidates copied from cited lessons. Their source reuse licences are unknown or unresolved, and fluent-speaker review is pending. Do not present them as approved translations.

## Draft inputs

`scripts/talk-factory/inputs.ts` exports `extractTalkDraftInputs`. It reads actual city and venue content through the scene brief extractor. It uses the recorded NPC role and exact effective venue-area labels as facts. It does not infer a person's job or residence. Callers must supply the city, region, voice, language, phrasebook, and selected phrases. Unsupported values fail validation rather than being shortened or aliased.

`scripts/talk-factory/draft.ts` exports `parseTalkDraftBinding` and `prepareTalkDraft`. A request asks for 60 unique lines in compact JSON. The prompt is capped at 16,000 bytes, uses at most 4,096 output tokens, and contains no player words or native phrase text. The reply is capped at 32,000 bytes and 7,600 UTF-16 units. The current shared gateway cutoff is 8,000 UTF-16 units.

## Runtime contracts

`server/story/talk-assets.ts` accepts only canonical bundled paths and bounded streamed bodies. Its Node counterpart rejects symlinks and oversized files. `talk-banks.ts` validates the index, full content hashes and city/venue/NPC bindings before exposing lines. It caches at most eight city loads and evicts failed promises so a later request can recover.

The service resolves the authenticated character's actual city, current venue, current regulars, opening hours, active action, Story lock and feature setting. It rechecks authority after asynchronous work. Asset replacement and player erasure invalidate pending responses. Greetings, farewells, hours, prices, directions and supported topics use filtered banks or current game metadata without requesting a model. Identity and crisis interceptions run first. Human phrases retain the beta mark and gloss.

Free text uses the existing `agent-talk` router purpose and existing providers. The live candidate preserves the whole question or falls back to a bank. It contains at most two messages and 250 UTF-8 content bytes, sends no conversation history, and allows 16 output tokens with a 1,500 ms router deadline. It asks for one complete English sentence of at most eight words. A whole trusted fact may be omitted when it would exceed admission. Replies still pass the existing output, minor-safety and contact filters and retain the AI mark. Missing sentence punctuation, ellipsis endings and obvious trailing conjunctions use the authored fallback with the attempted call's accounting retained. This rejects visible cutoff forms; it does not prove grammatical completeness. The hard 140-character output limit remains unchanged.

Before a paid attempt, a durable `session.once` receipt reserves the client ID with a digest of the bound request. It stores no conversation text. A matching local result can be replayed; after a restart or cache eviction, an already attempted request returns an explicit unavailable result instead of paying again. This is at-most-once admission within the existing 24-hour accepted-ID horizon. A crash after reservation may lose the reply. Expired IDs require an explicit new question. Existing player erasure removes the durable receipt; the runtime forget hook also cancels cached work.

Admission is the authorization point. Late location or generation changes suppress delivery; this adapter cannot cancel dispatches inside the protected router. The cost preflight sums conservative estimates across usable paid fallback candidates, including UTF-8 content bytes, framing allowance and host price ceilings. It admits an aggregate estimate of at most 90 microdollars. This is a routing estimate, not an invoice guarantee. The runtime's existing daily and per-player caps remain in force.

Local and operator environments that require a paid Story Talk path must explicitly configure `modelsAgentTalk` with one usable paid entry whose complete reservation fits that aggregate limit. An empty setting preserves the production default chain; a maximum-size prompt may then fail closed to an authored bank reply without a paid dispatch. This prerequisite does not change route defaults or select a production model. The additional catalogue entry still requires isolated availability, cost, latency and output-quality measurement before any later selection.

No-dispatch outcomes report known zero cost. A single clean success with reported usage exposes the router-booked amount. The router retains usage and provider-reported cost even when visible text is empty or rejected, settles failed attempts before fallback admission, and keeps the full conservative reservation as a debit when billing evidence is unknown. Its budget display distinguishes unresolved estimates from observed usage and explicitly states that it is not an invoice. The Talk response still reports unknown total provider cost for dispatched failures, preceding failed fallbacks and missing usage. Existing companion price environment values override effective router rates as well as the preflight estimate for the first configured companion model; they must not be described as admission-only values.

Two isolated standard-host measurements exercised the actual route and shared router before the sentence correction. Its metadata warmup plus turn took 2,428.609 ms, so it does not prove cold-start latency. The warmed text ended mid-sentence and failed quality acceptance. The corrected sentence handling passes 31 focused core, prompt, budget and route tests; actual revised-prompt quality, cold latency reliability and release integration remain open. Deterministic intents and same-ID repeats added no provider calls in both measurements.

The integrated billing correction now retains that evidence and conservative unknown debits; the historical failure remains recorded and a real corrected-provider measurement is still required. Nine separate bank checks across Kano, Accra and Tokyo passed for greetings, hours and directions with zero provider calls, distinct reply hashes, exact venue/NPC bindings, and the available beta phrase/gloss. These are API checks; browser and linguistic review remain separate. The additional catalogue entry is integrated without changing production model selection. Current endpoint prices, output quality and latency require a fresh isolated measurement before acceptance.

The client adapter substitutes each selected regular's own approved ambient lines. It preserves the original synchronous exchange while disabled or disconnected and falls back when either speaker's bank row is invalid. Actor, birth, city, venue, feature, connection, scene and playback generations fence the first and delayed second line. No player text or new stored state is added.

## Journal and runner

`scripts/talk-factory/journal.ts` provides `initializeFactoryJournal` and `openFactoryJournal`. A caller supplies one programme journal with a configured-exposure ceiling of USD 200, shared by drafts, GPU work, prior spend and unresolved reservations. The runner derives draft reservations from the fixed catalogue and price table. That estimate is not an invoice guarantee. The unchanged USD 2 runtime daily cap remains separate. Observed external factory spend is USD 0; worker compute cost is unknown.

`scripts/talk-factory/runner.ts` exports `planTalkRun` and `createTalkRunner`. It plans against the shared `agent-talk` gateway catalogue, uses two dispatch slots per entry, and applies a 60-second request deadline. Complete raw token usage is required for normal accounting. If usage is incomplete or a dispatch remains unresolved, the runner holds the full reservation. Pending authorization work must settle before fallback, publication or return; this durability check can outlast a cancelled request.

Publication uses a no-overwrite candidate, a content hash, directory synchronization, and verified readback before journal commit. Recovery checks the original binding, configuration, and target without another provider request. The filesystem checks assume cooperative same-user access; they do not provide hostile same-user compare-and-swap protection.
