The owner's goal in their words: there is a game mode and the normal free roam mode. Free roam is what currently exists and what users see; they can switch to the game mode. In game mode all maps and locations become locked and you play each city and location to progress as the map unlocks. Each player has a different experience based on where they live or start because missions and games are unique to each city. Every one of the 200+ cities gets a unique, realistic scene, all lazy loaded. NPC conversation uses local or cheap AI so it is unique per place, with various game styles. HARD RULES
- Free roam is byte-for-byte today's game. state.story.mode defaults to 'free' for every existing save; storyBlock() and venueOpen() return null when mode is not 'story'. Ladder progress is tallied in both modes and computed from receipts the player already holds (tale mementos, journey collections, the per-city tally); locks apply only in story mode. The switch is one action story.mode {mode}, reversible, no cooldown, shown in Passport and the Home chip, hidden when the admin setting storyMode is off.
- The four doors (relocateBlock, joinOp, homeward ticket, settleCity) and travelBlock all call the same pure functions from src/story/ladder.ts. A co-op helper pass lets a friend enter a locked city for a help session only and never changes the helper's own ladder.
- Budgets in src/budgets.ts are never raised; you may add new entries (CITY_SCENE_RECIPES_BYTES, SCENE_KIT_BROTLI, HERO_BROTLI) and their patterns in scripts/download-budget.ts. Startup raw has a 13-byte margin and scene-host gzip about 300 bytes. Nothing new may ride in the startup, engine or scene-host chunks. Story rules go in the lazy progression-rules chunk via progression-register.ts, never as a new file under src/game/ that the Vite rule would pull into the engine. Recipes, kits, heroes and talk banks are lazy per city through the existing city chunks and content assets (5 MB cap per city), with idle prefetch of linksFrom(current) cities held back on save-data and 2G. Run npm run size:download on every phase and fix anything that moves those numbers.
- New stored state is additive only: declare state.story in a system's stateKeys, rebuild it in sanitize(), never bump state.v, update freshReaders in src/game/progression-slices.ts. Every new stored thing is wired into player erasure.
- Every model call (factory scripts included) goes through routerOf(ctx).ask() or the same gateway code with the same price table; no new provider; respect the US$2 daily cap at runtime; factory scripts run offline with spend recorded in the record (budget US$200 total for drafts and GPU time unless the owner raises it). Every shipped NPC line passes agentWords({toMinor:true}) and the text filter at build time; live replies pass cleanReply, agentWords and ai-intercept; the AI mark is never dropped. Native-language phrases come only from human-written phrasebooks under scripts/talk-factory/phrasebooks/, marked beta.
- Scenes: every recipe passes validateRecipe (bounds, no overlap, every spot reachable, estimated triangles <= 15,000, meshes <= 13, lights <= 4, sign text filtered) and the existing per-venue tests in src/game/cities/allCities.test.ts and src/scene/city-scenes.test.ts (change the exact chunk-list assertion to a pattern). Kits <= 1,500 triangles per prop, one 1K WebP atlas, meshopt, <= 300 KB Brotli per kit. Heroes <= 4,000 triangles, <= 60 KB. Authored Nigerian cities keep their hand-written variants; the factory fills only venues without one.
- Licences: AGPL-3.0-or-later. OSM/Overture data stays ODbL-attributed in the game view and credits; ship baked recipes, never raw per-city footprint dumps. Wikidata is CC0. No Google 3D Tiles.
