## Compatibility and provenance rules

- Three r180 can load glTF/GLB through the current dynamic `GLTFLoader` path, but that proves file-format compatibility only. It does not prove a pack’s skeleton names, texture color spaces, alpha modes, pivots, scale, or triangle budget. Run every candidate through `src/scene/models/gltf-source.ts`, the existing Meshopt/gltfpack pipeline, and visual anchor checks.
- CC0 reduces copyright friction but does not guarantee absence of trademarks, recognizable logos, or culturally unsuitable art. Kenney and Quaternius pages state CC0; Poly Haven states its assets are original/CC0. Keep the exact source URL and selected file manifest with any accepted asset.
- Do not add a runtime asset dependency or download from a live API. Vendor only a reviewed, optimized derivative into the existing asset ownership lane.
- Asset pack code/art licenses are separate from Allworld’s AGPL code. Do not infer that a pack’s license applies to generated derivatives, bundled engine projects, or third-party textures inside a pack without checking its own notice.

## Small acceptance test

For either first import, use one fixed venue/city camera and one phone-tier fixture. Record source URL/license, selected file size, primitive/material/texture counts, triangles, texture dimensions/bytes, GLB decode completion, first visible frame, anchor/scale, shadow/readability, and disposal. Compare against the existing procedural stand-in and preserve the stand-in on failure. Stop before integration if the page does not provide a clear format/asset license, if conversion changes required animation/anchor metadata, or if the reduced asset breaks the current mobile budget.

No downloads, pack-size guesses, build, install, or source/test changes were made. The only byte sizes above are publisher-stated page sizes; Kenney and Quaternius pages expose counts/formats but not archive bytes.

## Four additional game-repository patterns

These are references for bounded patterns, not engine-switch recommendations.

1. **[PlayCanvas Engine](https://github.com/playcanvas/engine/tree/3b389e05a4619dcb2a6efec3bc8139bf43cafd95), MIT.** The official developer documentation describes batch groups that combine meshes to reduce draw calls ([batching guide](https://github.com/playcanvas/developer-site/blob/main/docs/user-manual/graphics/advanced-rendering/batching.md)). Portable pattern: make an offline “batch eligibility” report for Allworld’s existing same-material street props before merging; keep `src/scene/models/scene-models.ts` priority/near/far and labels as owners. **Study only**; the current gltfpack/merged-material path already covers much of this.
2. **[Babylon.js](https://github.com/BabylonJS/Babylon.js/tree/a6b8e226d46464328197447f9fc93054c7b494fb), Apache-2.0.** Babylon’s official thin-instance design documents one source mesh drawn thousands of times, per-instance matrices/colors, GPU buffer sync, and paired LOD state ([Babylon-Lite thin instances](https://github.com/BabylonJS/Babylon-Lite/blob/master/docs/lite/architecture/12-thin-instances.md)). Portable pattern: extend `src/map3d/city-build.ts`’s existing `InstancedMesh` only where one geometry/material and many transforms are proven; preserve current city limits and avoid adding Babylon runtime code. **Study** for vegetation/population batching.
3. **[Godot Engine](https://github.com/godotengine/godot/tree/befe24c83135da887e534504874d1dcea4ed1f1c), MIT.** `MultiMeshInstance3D` is a specialized instancing node over a `MultiMesh` ([official docs](https://github.com/godotengine/godot-docs/blob/master/classes/class_multimeshinstance3d.rst), [source](https://github.com/godotengine/godot/blob/befe24c83135da887e534504874d1dcea4ed1f1c/scene/3d/multimesh_instance_3d.cpp)). Portable pattern: keep per-instance transforms/colors in the city builder and use a single resource key for repeated trees/props; do not port Godot nodes. **Study** as a vocabulary for instance-data ownership; Allworld already has the correct Three `InstancedMesh` primitive.
4. **[Bevy](https://github.com/bevyengine/bevy/tree/12a94e0cd6b18df7a0dc2e5a202a55156d80e9a6), dual MIT/Apache-2.0.** The official `visibility_range.rs` example demonstrates distance visibility ranges with a main model and a lower-detail model ([example](https://github.com/bevyengine/bevy/blob/12a94e0cd6b18df7a0dc2e5a202a55156d80e9a6/examples/3d/visibility_range.rs), [license](https://github.com/bevyengine/bevy/blob/12a94e0cd6b18df7a0dc2e5a202a55156d80e9a6/LICENSE-MIT)). Portable pattern: make explicit authored LOD pairs for the new barrel/tree and register them in Allworld’s existing near/far model layer instead of adding automatic engine LOD. **Adopt the data rule only**: every new asset should declare near, far, and stand-in behavior.

None of these repositories grants rights to their sample art. Only the code patterns are being considered; downloaded models remain governed by their own asset licenses.
