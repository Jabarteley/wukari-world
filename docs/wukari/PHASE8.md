# Wukari Life: character and interface

Run `npm run wukari:play` from the repository, then visit **http://127.0.0.1:5196/**. The menu shows your saved character. Select **Customize Character**, choose an appearance, check Front / Side / Back, and select **Save character**. Close discards unsaved edits; Reset appearance previews the default until saved. Save applies to this browser/device. Browser storage restrictions are reported and leave a session-only appearance.

Choose **Play** to walk in the existing Wukari town area. WASD/arrows walk, Shift sprints, drag or Q/E rotates the camera, scroll zooms, and Escape opens the menu. On touch screens hold the directional buttons and tap Sprint to toggle it. The character faces the direction of travel, with smoothed rotation and blended breathing, walking and running. Settings persist camera sensitivity, graphics resolution and a future volume preference. **There is no audio yet.**

The original procedural character has eyes, pupils, highlights, eyebrows, nose, lips, ears, sculpted hair, hands, fitted clothing and shoes. Choices include eight skin shades, four hairstyles, three outfits, sneaker/boot styles, three body proportions and independent colors. It uses joint groups and merged geometry rather than downloaded character assets. Allworld's procedural character/rig/preview patterns were reviewed; its native model manifest references GLBs absent from this checkout. This implementation adds no external asset licence, dependency or asset pipeline. Code and original procedural art retain the repository's AGPL-3.0-or-later licence. The small versioned appearance record is independent of map and account state and can later be carried by a multiplayer profile.

**Explore Map** or **Map Information** opens the existing geographic experience. Map Information keeps source links, exact OSM IDs/tags, provenance, coverage and limitations. Its FUW location review remains non-spawning: neither a surveyed campus boundary nor ownership/access is established. Town spawning is the owner's reviewed simulation-only permission. It does not establish real-world pedestrian safety or access. Geography/imports, buildings and the database were not changed. See [Phase 7](PHASE7.md) for geographic coverage and verification.

## Validation and limits

- Focused suite: `node --test src/wukari/*.test.ts scripts/typecheck.test.ts` (55 passed on final source; avatar/movement subset 9/9). Includes source geometry, restrictions, building collisions, movement speed, bounded persisted records, proportions, finite animation transforms, facing and geometry disposal.
- Strict Wukari Vue/TS check: `node node_modules/vue-tsc/bin/vue-tsc.js --noEmit -p scripts/wukari/tsconfig.json`. That tracked focused config extends the root base, uses node/vite/client and ES2023/DOM/DOM.Iterable, and includes src/wukari TS/Vue, scripts/wukari TS and env.d.ts.
- Production: `npm run wukari:build`, output `dist/wukari-play`. Vite retains a >500 kB chunk advisory (mostly Three.js); no warning suppression or baseline increases.
- Chromium/CDP: `node scripts/wukari/play-browser.ts` with the local server running. Checks live customization/save/reload, settings, preview removal, lazy FUW loading/non-spawning, walk/sprint, camera, collision/corridor, map pause, touch movement/release/sprint/look and exploration. Screenshots and structured results are in `evidence/phase8-*`. Mobile uses a 390×844 emulated viewport/touch input, not physical-device benchmarking. Software-rendered frame rates are not phone/GPU performance guarantees.
- Avatar geometry is merged by joint/material. Preview rendering exists only while a menu is open; closing disposes its geometries/materials, observer, animation loop, canvas and WebGL context. Map switches dispose the world renderer/context as well. Graphics presets cap DPR at 1 / 1.5 / 2; they do not imply different geographic detail.
- **Full-project typecheck is not certified clean.** The previous investigation remains applicable: ES-only engine imports of browser `fetch`; Worker TextDecoder option mismatch at server/accounts/token.ts; and implicit-any `.test.mjs` inclusion/ownership. Previous complete runs did not finish under memory pressure. See [the exact prior evidence](evidence/phase7-types.json). This milestone checks the Wukari slice and does not change unrelated types, baselines or guards. No full-project pass is claimed.
