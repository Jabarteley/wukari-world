# Country batch pipeline (table-driven)

One reusable lane for any country: a table of 1 to 6 cities in ONE country goes in, the pinned Geofabrik PBF is downloaded and hashed once, one same-source admin-0 boundary is built, all cities are extracted from shared scans, the factory checks run, and per-city module output plus receipts come out. Every stage reports an explicit HOLD reason per country and per city. Nothing here is acceptance: output is `SOURCE_CANDIDATE` then `GENERATED candidate`; visual review, bounds review and the "Parallel city acceptance" run stay separate.

Hosted triggers live on branch `claude/factory-20261012` only and fire only on a push that touches a queue file:

| Stage | Workflow | Trigger path (queue) | Lane |
|---|---|---|---|
| B. source batch | `.github/workflows/country-source-batch.yml` | `scripts/geo/factory/country-queue.json` | concurrency group `country-source-lane`, matrix `max-parallel: 1`, `fail-fast: false`, 240 min limit |
| D. factory candidate | `.github/workflows/country-factory.yml` | `scripts/geo/factory/country-factory-queue.json` | group `country-factory-lane`, `max-parallel: 1`, 60 min limit |

A failed or timed-out entry ends its own job; the lane is free for the next matrix entry and the next run. A missing, deleted or empty (`"queue": []`) queue file is a no-op (plan job only, no downloads). Templates: `country-queue.example.json`, `country-factory-queue.example.json` (the example names do not match the trigger paths).

## Adding a country (exact steps)

1. Choose cities (1 to 6, same country). Find real values; never type pins from memory:
   - PBF: dated Geofabrik file `https://download.geofabrik.de/<region>/<country>-YYMMDD.osm.pbf`. `curl -sIL <url>` for `Content-Length` (bytes); `curl -sL <url>.md5` for MD5. The `snapshotDate` must equal the YYMMDD in the URL.
   - Airport: OurAirports `ident` (pinned CSV commit in the example), same country, type large/medium/small, `scheduled_service=yes`. Without an `airport` selector the picker matches by municipality and HOLDs on ambiguity. Exception: `airport.hubWaiver` (see "Airport hub waiver").
   - Timezone: id exactly as a row for the country in the pinned `bootstrap/timezone-data/zone1970.tab` (tzdb 2026e). zone1970 merges zones: Netherlands is `Europe/Brussels` (line `BE,LU,NL`), Lesotho is `Africa/Johannesburg`. The validator names the missing id before any download.
2. Write `scripts/geo/factory/country-tables/<cc>.json` (cc = lowercase ISO 3166-1 alpha-2). Worked example: `country-tables/examples/nz.json` (two cities, with `selectionExclusions`).
3. Validate offline (no network, no output dir): `python3 -I scripts/geo/factory/bootstrap/batch-run.py --table scripts/geo/factory/country-tables/<cc>.json --validate-only` must print `"status": "VALID"`.
4. Write `scripts/geo/factory/country-queue.json` (up to 4 countries, one entry each): `{"schemaVersion":1,"queue":[{"id":"<cc>","table":"scripts/geo/factory/country-tables/<cc>.json","appSha":"<40 hex>"}]}`. `appSha` = app commit the factory generates into (it becomes `expectedSourceGitSHA`; it must contain the app files listed in runner.mjs `shared`, and be pushed to the repo). Check offline: `node scripts/geo/factory/country-queue.mjs --kind source --queue scripts/geo/factory/country-queue.json`.
5. Commit and push ONLY `claude/factory-20261012`. The source workflow runs. Download: `gh run download <run> -R kromate/joinallworld -n city-bootstrap-<cc>-<github.sha> -D /private/tmp/<cc>-bootstrap`.
6. Read `receipts/result.json`. Root `status` is `SOURCE_CANDIDATE` or `HOLD` with `reason`; `cityResults[]` has one row per city with `status` and `reason`; `countryBoundary` has `status: HOLD` when the boundary failed (then every city is HOLD). Per-city diagnostics: `logs/<id>-metadata.log`, `metadata/<id>/candidate/city-candidates.json`, `logs/<id>-extraction.log`, `logs/batch-extraction.log`, `receipts/stages.jsonl` (stage timings).
7. The artifact also holds `factory-table-draft.json` (generated by `bootstrap/table.mjs` inside the run from the verified artifact; held cities are excluded and listed in the step log). Copy it to `scripts/geo/factory/country-factory/<cc>-factory-targets.json`. Optional top-level `"receiptRoot": "world/playable-<region>-rollout"` (default `world/playable-africa-rollout`). 1 to 5 targets per table.
8. Write `scripts/geo/factory/country-factory-queue.json` with `{"id":"<cc>","table":"scripts/geo/factory/country-factory/<cc>-factory-targets.json"}`, commit both, push. The factory workflow checks out the app at the table's `expectedSourceGitSHA`, verifies producers and hashes, and runs selection, scaffold, generation, source scene, map/journey tests, flat proofs and receipts.
9. Download `city-factory-<cc>-<N>targets-<github.sha>`: `evidence/machine-holds.json` (pass = `machineFailed:false`, `catalogue:true`), `delivery/cities/<id>/`, `delivery/recipes/<id>.ts`, `delivery/<receiptRoot name>/receipts|sources/<id>.json`, flat PNGs under `evidence/<id>/proof/`. LOOK at the PNGs. Import per FACTORY-RUNBOOK.md stage E (copy delivery files, `npm run cities:catalogue`, `npm run cities:assets`; never apply `generated.patch`).

After a run, reset the queue to `{"schemaVersion":1,"queue":[]}` (a push of an empty queue only runs the 15 s plan job). Two queue pushes in quick succession: GitHub keeps only the newest pending run, so put several countries in one queue.

## Importing a delivery (import-delivery.mjs)

`node scripts/geo/factory/import-delivery.mjs --app <app worktree> --deliveries <dir> [--cities a,b,c] [--replace]`

`<dir>` holds one sub-folder per downloaded artifact (`gh run download <run> -R kromate/joinallworld -n city-factory-<cc>-<N>targets-<sha> -D <dir>/city-factory-<cc>-<N>targets-<sha>`). Per city it checks `evidence/machine-holds.json` (`machineFailed:false`, `catalogue:true`, every `machineStages` true), the receipt (`cityId`, `inventoryPath`, `inventorySha256` against the delivered sources file) and every output hash pinned in `evidence/step-cache.json` that maps to a delivered file (module files, proof JSON/PNG). It refuses a city already present in the app (module folder, recipe, receipt or sources) unless `--replace`. Then it copies `delivery/cities/<id>` to `src/game/cities/<id>`, `delivery/recipes/<id>.ts` to `scripts/geo/destination-detail/<id>.ts`, and `delivery/<receiptRoot>/{receipts,sources}/<id>.json` to `world/<receiptRoot>/...`. Other cities' receipts in the delivered rollout folder are ignored. It never applies `generated.patch`, never runs npm, and writes no generated file. It prints a per-city IMPORTED/REFUSED report plus the follow-up commands (`npm run cities:catalogue`, `npm run cities:assets`, `check-playable-africa-rollout.py <ids>`, typecheck, the city tests) and exits 1 on any refusal. Rehearsed on gw/bissau and cv/praia (run 38246543387): catalogue, typecheck, rollout checker and 10 node tests passed. Machine PASS is not acceptance: look at the flat PNGs, review centre and airport, then commit and use the SHA as `appSha`.

## Generating a table (make-country-table.mjs)

`node scripts/geo/factory/make-country-table.mjs --spec <spec.json|inline-json> --out <dir> [--airports-commit <40hex>] [--max-km 60]` writes `<out>/<cc>.json` (the table) and `<out>/<cc>-notes.json` (what was proposed or checked, sources, retrieval times). Node only, no dependencies; needs network (Geofabrik, GitHub API, raw.githubusercontent.com). Always run `batch-run.py --table <file> --validate-only` on the result.

Spec (one object, an array, or `{"countries":[...]}`): `{"iso":"LR","country":"Liberia","geofabrik":"africa/liberia","cities":[{"id":"monrovia","name":"Monrovia","lat":6.31,"lon":-10.80,"centreSource":"Wikidata Q3748 P625","airportIdent":"GLRB"}]}`. Optional per city: `timezone` (IANA id), `airportSourceUrl`, `hubWaiver` (a written reason of at least 20 characters, see "Airport hub waiver": the named `airportIdent` may then be a heliport, seaplane base or field with any `scheduled_service`; refused when the country has a scheduled large/medium/small airport) and the pass-through seed fields `cityOsmRef`, `sceneWaterExtent`, `namesUnit`, `selectionExclusions`, `profile`, `geometry`, `playBox`. Optional per country: `geofabrikDate` (`YYMMDD`: pin that dated file directly instead of following `-latest`, needed when `-latest` redirects to a mirror, e.g. Germany, and to keep several files on one snapshot), `neighbours: [{geofabrik, reason}]` and `cityExtract: {geofabrik, reason}` (pinned at the same date; the city extract also pins both `.poly` files). The specs of the microstate batch are kept in `country-tables/specs/` (regenerate a table with `GITHUB_TOKEN=$(gh auth token) node make-country-table.mjs --spec country-tables/specs/<cc>.json --out <dir> --airports-commit 03565b612558de9d9ec27ca7a1e99a4f9d2619ba`).

- PBF pin: HEAD on `<path>-latest.osm.pbf`, follows the redirect to the dated file (or `geofabrikDate`: the dated file directly), bytes from `content-length`, md5 from the `.md5` sidecar, snapshot date from the YYMMDD in the name. The table never contains `-latest`. Single-segment paths (`russia`) are accepted.
- Airports pin: latest commit touching `airports.csv` in `davidmegginson/ourairports-data` (GitHub API), raw URL by that commit. Pass `--airports-commit` to reuse one pin across batches (also avoids the unauthenticated API rate limit; `GITHUB_TOKEN` is used if set and never printed). The CSV is downloaded to check the ident: large or medium airport, same country, `scheduled_service=yes`, within `--max-km` (default 60) of the spec lat/lon. If `airportIdent` is omitted the nearest such airport is written as a proposal: the notes file says `"proposal": true` with alternatives, the run prints `AIRPORT PROPOSED`, and a human or helper must review it before queueing. The default `airport.sourceUrl` is the OurAirports page; set `airportSourceUrl` for a better provenance link.
- Timezone: from the pinned `bootstrap/timezone-data` (hash-checked against `timezone-source.json`) by ISO. One zone1970 row for the country is used automatically; several rows refuse unless the city sets `timezone`.
- No guessing: `lat`, `lon` and `centreSource` are mandatory per city. Helpers take the coordinates from an authoritative source (GeoNames or Wikidata P625) and cite it in `centreSource`. They are used only for the airport distance check and recorded in the notes; the pipeline still derives the real centre from the OSM node.
- Any failure (redirect missing, bad md5 sidecar, unknown ident, wrong type, no scheduled service, too far, ambiguous timezone) prints `REFUSED - <reason>`, writes nothing for that country and exits 1; other countries in the same spec file are still written.

## Table fields (schemaVersion 2)

Top level: `geometrySourceSha` (must be `7a57e756a10b35a0eec9ec5928f083580fb9e7a9`), `countrySource{url,bytes,md5,snapshotDate,neighbours?,cityExtract?}` (unknown keys rejected; `neighbours` see "Neighbour extracts", `cityExtract` see "City sub-extract"), `airports{url,commit,snapshotDate,commitTimestamp}` (url must be the raw githubusercontent URL of that exact commit), `seeds[1..6]`.
Seed (`bootstrap/seed-contract.schema.json`; unknown keys are rejected): `id` (kebab-case), `name` (matches an OSM `place=city|town` `name` or `name:en`), `countryISO` (all seeds the same), optional `cityOsmRef` (`node/<id>`, picks among matching nodes), `airport{ident,sourceUrl,hubWaiver?}`, `timezone{id,sourceUrl}`, `profile` (`microstate`; absent = standard, see "Seed profiles"), `geometry`, `playBox` (per-seed knobs, see the geometry knobs section), `sceneWaterExtent` (`play`|`reach`), `namesUnit` (string), `selectionExclusions[{ref,reason}]` (OSM refs removed from the venue pool; a ref absent from the candidate set HOLDs). Derived, not written: centre (OSM node), airport lon/lat (CSV row), country name, `state.idunique`, bounds, five extract layers, boundary.

## Reviewed boundary evidence and skipped relations

Two rules added after the 2026-10-12 source holds (run 38248346879; diagnosis in the world ledger). Both change `country-boundary.py` / `offline-extract.py` and therefore the boundary script hash and the adapter hash: they apply to NEW source runs only. Receipts and pins of already accepted countries and cities are unaffected.

Country boundary, absent member ways (`bootstrap/country-boundary.py`):
- Default is unchanged: every `w` member of the admin-0 relation must be in the clipped PBF, otherwise HOLD.
- Exception: `bootstrap/boundary-evidence/<cc>.json` (picked up by `batch-run.py`, passed as `--absent-evidence`). The file lists exactly the absent way ids with version, timestamp (not newer than the PBF header), tags and first/last node, and `datasetSha256`, which must equal the SHA-256 of the PBF of that run. Evidence therefore cannot be reused on another snapshot, and a way set that differs from the actually absent set HOLDs.
- Only `maritime=yes`, `boundary=administrative`, `admin_level=2` ways qualify, and only whole separate rings: the absent ways' endpoints must pair up among themselves (a closed way pairs with itself) and no endpoint may be a node of a present boundary way. An absent way that belongs to the main ring (bz, hn, pa, kg, sr) still HOLDs, as do the land exclaves am, az, uz (no evidence is added for them); those countries use neighbour extracts instead (next section).
- The omitted ways are listed in the receipt (`absentMemberPolicy`: ids, versions, tags, evidence SHA-256). A derived mini-PBF (relation minus those ways, present ways and nodes unchanged) goes through the unmodified osmium area assembler and the existing complete-segment proof, so the remaining rings must still assemble and match every present segment. `country-scope.mjs` reads the policy and carries it into the scope proof.
- Node members of any role (admin_centre, label, capital, highest_point, ...) are non-boundary references listed in the receipt (sk).
- Evidence now: `ht`, `my`, `to` (Navassa, Sabah/Spratly and Minerva Reef territorial rings), each pinned to the PBF of run 38248346879.
- Whole separate rings that are not maritime (`wholeSeparateRings`, 2026-10-13, owner decision for France): an evidence file that sets `"wholeSeparateRings": true` and a written `reason` (20 characters or more) may also list non-maritime admin_level=2 boundary ways (land and river border ways of overseas departments and territories). ## Per-seed geometry knobs and play box (`seed.geometry`, `seed.playBox`, 2026-10-13)

Why: a dense coastal city can exceed the 90,000-triangle scene budget under the shared `standard` preset (Singapore 99,461 with the current exact-coast stage, 112,831 before it). The seam lets one seed change recipe numbers and the play box without touching any other city.
- `seed.geometry` (factory stage): any of `waterTolerance`, `outlineTolerance`, `farTolerance`, `coreTolerance`, `minWaterKm2`, `maxRoads`, `minRoadKm`, `cell`, `split`, `seaBandMetres` (ranges in `bootstrap/geometry-knobs.json`, one list read by `batch-run.py`, `table.mjs`, `batch.mjs`). Only the named keys replace the preset; the effective numbers are written into the recipe `CONFIG` and `selection/check-table.json` (`geometryKnobs`). Flow: table seed -> source `result.json` city row -> `factory-table-draft.json` target `geometry` -> `batch.mjs`. `runner.mjs` pins the knob file as a tool.
- `seed.playBox` (source stage): `playKm` (default 20) and `coreKm` (default 5), km half-widths passed to `bounds.mjs --play-km/--core-km`; the 1 km airport box still joins the play box, so the box is not symmetric when the airport lies outside the radius. The proposal records the policy in `bounds.json`. It changes the extract boxes and so the extract hashes: it needs a new source run.
- App baseline 31e7799c facts (measured): `outlineTolerance` is capped at 0.00015 inside `build-destination-detail.ts` (`Math.min`), so raising it changes nothing; `sea.bandMetres` changes nothing; `farTolerance`/`coreTolerance` save about 100 triangles; `waterTolerance` is NOT monotonic after the exact-coast stage (0.0008 saved 7.9k on the 20 km box and cost 15k on the 14 km box); `maxRoads` and the play box are the dependable levers. Measure every city again after a change.
- Singapore replay (offline, hosted source artifact 38208407941 extracts and a local 261010 PBF, factory runner, all stages): see `country-tables/sg.json` (`geometry.maxRoads` 600, `playBox.playKm` 14: 84,641 triangles, 16 draw calls, all machine stages pass).
- Tests: `python3 -m unittest scripts/geo/factory/bootstrap/test_geometry_knobs.py`.

## Exact-coast fix (2026-10-13)
`exact-coastwater.py` chose the faces of the play tiling by a representative point of each face; for a tiny face that is exactly an island of the water (two islets near Tuas) the point can lie on the shared boundary, `covers` was true, the islet became water and the stage failed with `FinerWater: Serialization changed coverage/topology`. A face now also needs the water to cover more than half of its area. The error message now carries area fraction, both topologies and contact counts. Singapore passes the stage after this.

## Neighbour extracts (`countrySource.neighbours`)

Owner rule: fix incomplete boundary or coast data with a COMPLETE COMPATIBLE source, not mixed-snapshot splicing. Geofabrik clips a country by its own polygon and keeps a way only when one of its nodes is inside, so a border segment, an exclave ring or a maritime closing line of the admin-0 relation (ss, kg, sr, am, az, uz, bz, hn, pa), or the coastline just past a border (sl Freetown, dj Djibouti), can be absent. The same objects are in the neighbouring country's extract of the same snapshot.

- Table: `countrySource.neighbours: [{url, bytes, md5, snapshotDate, reason}]`, 1 to 3 entries. Each `url` is a dated official Geofabrik file whose YYMMDD equals the primary's, `snapshotDate` equals the primary's, `bytes`/`md5` from `curl -sIL` / the `.md5` sidecar, `reason` names the absent ways or coast it supplies. Anything else (another date, a `-latest` file, another host, a repeated URL, extra keys) is rejected by `--validate-only`, so the lane never starts on it. Choose the fewest and smallest neighbours: test which neighbour's `.poly` contains nodes of each absent way (the HOLD names them in `country-boundary/result.json` `diagnostic.missingMemberWayIds`).
- Run (`bootstrap/batch-run.py`): downloads the primary and every neighbour, verifies each byte count and MD5, then `bootstrap/source-merge.py` merges them into `downloads/merged.osm.pbf` (stage `source-merge`). The merge is a streaming sorted union with the pinned pyosmium 4.3.1 (the workflow has no osmium-tool CLI; the semantics equal `osmium merge`): every input must carry the same `osmosis_replication_timestamp` on the snapshot date (copied into the merged header), and an object present in several inputs is written once and must have the same version, tags and nodes/members/location in every input; any difference is a HOLD, never a choice. The inputs are deleted after the merge.
- Everything after that is unchanged and reads the merged file: boundary assembly (`country-boundary.py`), city metadata and extraction (adapter hash unchanged). The dataset identity is the MERGED file: `datasetSha256`, `bytes`, `md5` everywhere are the merged file's; `datasetUrl` stays the primary URL. ## Exact coast stage (exact-coastwater.py, runner stage `exactCoast`)

Why: the app generator (baseline `build-destination-detail.ts`, `shoreWater`) finds the sea by a grid flood fill and calls a region land when a place of the game lies in it. A place that lies on the shore or offshore (a port node, a rock in the sea) marks the sea as land, and a coast way that the country extract cuts at the border leaves a gap the fill leaks through: the sea comes out as land (Praia, Djibouti, Port Louis, Freetown) or islands are drowned (Bissau).
What it does, per city after generation (inland cities report `not-applicable`; the generator's own files are untouched then): builds land and sea from the SAME pinned `water.json` coastline ways (OSM direction: land on the left), compares that with the generator's sea, and
- `generator-validated`: the generated sea agrees (under 1% of the ground box differs, ignoring 150 m round the shore): nothing is rewritten;
- `passed`: otherwise terrain.ts `water`/`reachWater` and geometry.ts `playArea` are rewritten from the exact sea (play box simplified at 1 m, 2 m if the scene budget needs it; the backdrop beyond the play box coarser and without sub-2000 m2 islets; rings re-started so the renderer's ear clipping is faithful; all reported in `<id>/coast-water.json`). Coast ways cut at the country border (outside the pinned admin-0 polygon, within 10 km) continue along their last direction to the edge of the ground box (the neighbour's land is never drawn); every other open end fails with its coordinates.
Batch 10 (2026-10-13): an unmatched coast end OUTSIDE the pinned country that lies within 3 km of the wide-box edge (not only within 10 km of the border) also continues in its last direction to the box edge, under the same rule (it may not run through the country; the report records `viaClipEdge` and `clipEdgeDistanceMetres`; Tel Aviv, whose Gaza coast chain stops 1.5 km short of the south edge). And `sceneWaterExtent: play` now also applies when the generator's own sea is kept (`generator-validated`): reach water is replaced by the play water (Ho Chi Minh City, Manila). Replayed offline on lk, mu and gw: output files byte-identical to the previous script.

It fails (HOLD) rather than draw wrong: an unclosed coast, a wet source place (all listed at once: add them to `selectionExclusions`), an offshore place. Needs `shapely==2.1.2` (installed in country-factory.yml) and node.

## Budget-aware water ladder (`waterBudgetLadder: true`, 2026-10-13; OFF unless the target sets it)
Why: a canal-rich city can still overflow the 90,000-triangle scene budget after `sceneWaterExtent: "play"` (Amsterdam: factory run 38336723513 failed only `sourceScene`, 121,181 triangles with the reach layer; with `play` the standard shore gives 100,244). The stage's own ladder is by water VERTICES (15,000) and steps finer, never by triangles, and the 0.01% area guard decides the shore.
Rule (`water-ladder.mjs`, `runner.mjs`, `exact-coastwater.py`): the target table key `waterBudgetLadder: true` (boolean; validated in `batch.mjs`, `bootstrap/table.mjs`, `batch-run.py`, `seed-contract.schema.json`, passed through by `make-country-table.mjs`; NOT written to the recipe) lets the runner treat the source-scene proof as the authority. When `sourceScene` fails ONLY on the triangle count (`budgetOverrunOnly`: every other assertion of `assertSourceScene` still holds), the runner restores the generated `terrain.ts`/`geometry.ts` that the exact-coast stage replaced (kept in `evidence/<id>/pre-exact/`), runs the stage again with the next coarser fixed rung and measures the scene again: 0.00001, 0.000015, 0.00002, 0.00003 degrees (about 1.1, 1.7, 2.2, 3.3 m), only rungs coarser than the attempt that overflowed, in that order, stopping at the first scene that fits, at a rung the shore cannot meet (exit code 3, recorded `infeasible`), or at a failure that is not the budget. Deterministic (no randomness; repeating a rung gives identical files).
Fidelity: the standard guard (0.01%) is never relaxed silently. A rung runs with `--ladder-tolerance-degrees` and `--ladder-area-cap` 0.001 (0.1%); the guard still applies at that cap to the fraction of the PLAY-box water that differs from the exact source water (the stricter of the stage's two figures), topology (components, holes) must be unchanged, no anchor or islet representative may become wet, land is untouched. The accepted (or, when no rung fits, the standard) attempt's report becomes `evidence/<id>/coast-water.json` with `toleranceLadder` (rule, caps, every attempt with tolerance, water vertices, whole-water and play-water area fractions, triangles, outcome, and `accepted`; the stage adds `toleranceLadder.measuredPlayWaterAreaFraction` and `relaxesStandardGuard` inside each rung's own report); every attempt's report stays beside it (`coast-water-rung-N.json`, `proof/scene-source-rung-N.json`). The row carries `waterBudgetLadder` and a warning in `machine-holds.json`. With the key absent nothing changes (checked: the exact-coast output of the standard path is byte-identical to the previous script).
Measured (nl Amsterdam, offline replay of the real `runner.mjs --execute` on the source artifact of run 38313119499 and the app baseline 31e7799c, all 8 machine stages): standard shore 0.56 m 100,244 triangles; 1.1 m 94,148; 1.7 m 90,264; 2.2 m (0.00002) 87,596 FITS with play-water area error 0.080% (whole-water 0.0187%), 19,662 water vertices, 490 holes, 33 polygons unchanged.

## City sub-extract (`countrySource.cityExtract`, owner decision 2026-10-13)

For very large countries (US 12.2 GB, CA 6.5 GB, DE 4.9 GB, RU 4.2 GB) a scan of the national file for one city needs a location index of the whole country (beyond a 16 GB runner) and hours. Rule: the exact same-source admin-0 boundary still comes from the FULL country file (plus same-snapshot neighbours as needed); the city's metadata and its five layers come from a same-date official Geofabrik regional sub-extract that contains the city.

- Table: `countrySource.cityExtract: {url, bytes, md5, snapshotDate, reason, polyUrl, polySha256, primaryPolyUrl, primaryPolySha256}` (exactly these keys; `$defs.countrySourceCityExtract` in `bootstrap/seed-contract.schema.json`). `url` is a dated official Geofabrik file of the primary's YYMMDD (not the primary or a neighbour) and smaller than it; `polyUrl` / `primaryPolyUrl` are the `.poly` files published beside the extract and beside the primary (`<region>.poly`), pinned by SHA-256 (the generator pins them). - Run (`batch-run.py`): downloads the primary, every neighbour, the city extract and both `.poly` files; verifies bytes/MD5 (`.poly`: SHA-256); requires ONE `osmosis_replication_timestamp` on the snapshot date in the primary, neighbour and city-extract headers (`city-extract-headers` stage) and a header box on the city extract. ## Memory-bounded admin-0 boundary (`country-boundary.py`, 2026-10-13)

The boundary no longer scans the whole PBF with a location index. Per input it streams three passes with the pinned pyosmium (one object type each, ids filtered in C++ by `osmium.filter.IdFilter`, the `osmium getid` semantics): admin-0 relations -> member ways -> the nodes of those ways, written to a small sorted closure PBF; several inputs (city sub-extract mode: primary + neighbours) are united with the `source-merge.py` identity rule. Member checks, area assembly and the segment proof then read the closure exactly as they read the whole file before (same objects; the synthetic test checks the geometry is byte-identical to a full scan). Memory does not grow with the file: the C++ id filter is a dense bitset over the id range, so the node pass peaks at about 1.7 GB whatever the input (13.5e9 node ids; measured 1.6 GB for 67k ids spread over that range), plus the boundary objects themselves. Measured on the real asia/kazakhstan-261011 file (224 MB, KZ relation 214665, 1,157 ways, 67,241 nodes) on a laptop: old full scan 15.4 s and 2.65 GB max RSS, new 2.0 s and 1.47 GB, `boundary.geojson` byte-identical (sha256 270adf05...) and receipts equal except `closure` and `scriptSha256`. The 6-12 GB files (US, CA) are proved only by the hosted run; expected peak under 2 GB for the boundary stage. The receipt records `closure` (per input: relation present, member ways, nodes, seconds). The script hash changes: new source runs only.

Reviewed absent-way evidence, two additions: (1) the evidence may name its PBF by `dataset: {url, bytes, md5}` (the pins the download was verified with) instead of `datasetSha256`, exactly one of the two, so a file whose SHA-256 is not known before the run (the 12 GB US file) needs no throw-away first run; (2) an evidence way may carry `tagException: {missingKeys, reason}` excusing only ABSENT `boundary`/`admin_level` keys of a `maritime=yes` way, with a written reason of at least 20 characters (US way 42296616, USVI Saint Croix ring, which has neither tag). `country-scope.mjs` applies the same rule to the receipt.
